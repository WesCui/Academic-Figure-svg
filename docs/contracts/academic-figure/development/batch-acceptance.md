# Batch Acceptance Rules

一个开发批次只有同时满足以下条件才可以标记完成。

## 范围

- 只修改批准文件；
- 没有顺手重构；
- 没有提前实现后续批次；
- 没有未批准依赖变化；
- 没有未说明的公共接口变化。

## 功能

- 批次 Contract 的所有必须项已完成；
- 非目标保持未实现；
- existing / planned 状态更新准确；
- 不把部分能力宣称为完整能力。

## 兼容性

- 现有 MCP 工具兼容要求满足；
- `document.json` 权威状态未被破坏；
- parser / serializer 往返未被无意改变；
- revision 行为符合批次约束；
- SVG-Edit 现有能力未被重复建设。

## 验证

- 批次要求的测试已运行；
- 测试结果逐项报告；
- 未运行测试明确说明；
- 失败测试不得隐藏；
- `git diff --check` 通过；
- `git diff --stat` 与计划一致；
- diff 中没有越界文件。

## 文档

- 实际行为与 Contract 一致；
- 新增限制已记录；
- 未完成项已记录；
- 仓库事实只在有代码证据时更新为 existing。

## 交付

交付物至少包含：

- patch 或明确的本地改动；
- manifest；
- validation report；
- 变更摘要；
- 测试结果；
- 未完成项；
- 风险；
- 回退方式。
